The system

One workbench.
Four intelligence layers.

01

Route

Automatically select the right model for the right task, based on what the work actually requires.

02

Act

Plan, execute, observe, critique and replan — instead of returning a single unchecked answer.

03

04

Prove

Prove what happened through audit trails and verifiable air-gap enforcement.

Agentic execution

It doesn't just answer.
It acts.

A task is decomposed into steps. Each step is executed, observed and critiqued before the next one begins — and the loop can revise its own plan.

01

Plan

Break the request into an ordered set of executable steps.

02

Execute

Run each step through a permitted model or sandboxed tool.

03

Observe

Capture the result of the step and what it changed.

04

Critique

Check the output against the source material and the task.

05

Replan

Revise the remaining steps when the critique finds a gap.

Grounding

Every answer points
back to a page.

Retrieval runs against the organisation's own documents. The answer carries the document, the revision and the page it came from — and abstains when the evidence isn't there.

SOP-PIP-014Revision R4
Page 12

Thickness readings below the minimum permitted value require an engineering assessment before the line is returned to service.

PAGE 12 / 46REV R4 · CURRENT
Grounded answer 1 source · 1 citation

The reading recorded in the inspection report falls below the minimum permitted thickness, so the line cannot be returned to service on the inspection result alone. An engineering assessment is required first. SOP-PIP-014 · R4 · p.12

No other clause in the retrieved set addresses the return-to-service condition, so nothing further is asserted.

Revision awareness

Superseded revisions are not treated as current guidance.

Abstention

Where the evidence is absent, the system says so rather than filling the gap.

Page-level citations

Each claim resolves to a document, revision and page.

Air-gapped by design

Your data doesn't travel to the AI. The AI comes to your data.

The workbench is installed inside the controlled environment. Models, tools, knowledge and the audit record all sit on the same side of the boundary, and outbound traffic is denied by default rather than filtered after the fact.

Architecture

Built as infrastructure,
not as an add-on.

LAYER 01

User / UI

The workbench surface where tasks are submitted, reviewed and approved.

LAYER 02

Orchestrator

Decomposes the task and drives the plan–execute–observe–critique loop.

LAYER 03

Router

Classifies the task and selects the model best suited to it.

LAYER 04

Model registry

The set of approved open-weight models available on the host, with their capabilities.

LAYER 05

Model serving

Local inference on the organisation's own hardware.

LAYER 06

Tools

Sandboxed execution with allowlists and permission-aware access.

LAYER 07

Knowledge / data

The document pipeline and local vector store built from internal material.

LAYER 08

Host isolation

Network policy, egress denial and the local audit store underneath everything above.
